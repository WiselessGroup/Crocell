# Как помочь Crocell

[English](CONTRIBUTING.md) &nbsp;|&nbsp; **Русский**

Задачи и пул-реквесты живут на [GitHub](https://github.com/WiselessGroup/Crocell). Писать можно по-русски или по-английски.

## Можно и без кода

Сейчас полезнее всего хороший отчёт об ошибке. Все провайдеры и все сети я проверить не могу, поэтому сообщение, что подписка не разобралась или нода умерла на вашей системе, часто единственный способ об этом узнать.

**Прежде чем что-то публиковать, помните: ссылка на подписку это ключ от вашего VPN.** То же самое со ссылкой `vless://` и с конфигом. Кто их прочитает, тот сможет тратить ваш трафик. Кнопка «Логи» в приложении вырезает ссылки на подписки из копируемого текста, но всё равно просмотрите его глазами. Если не разбирается какой-то формат, пришлите его структуру, заменив сервер, UUID и ключи.

В хорошем отчёте есть версия Crocell, система, режим (прокси или туннель), протокол ноды и логи. [Форма для ошибок](https://github.com/WiselessGroup/Crocell/issues/new?template=bug_report.yml) спросит всё это сама.

## Перед большой правкой

Если это не просто исправление ошибки, сначала заведите задачу. Две вещи вряд ли пройдут:

- **Новое на первом экране.** Короткий первый экран это причина, по которой Crocell вообще появился. Новые опции идут в настройки, и только если приложение не может решить само.
- **Телеметрия, аккаунты, реклама.** Без исключений.

Третьему языку я буду рад, но тексты лежат в коде парами `tr('ru', 'en')`, так что придётся менять сам подход. Давайте сначала обсудим.

## Что поставить

Нужны [Go](https://go.dev/dl/) 1.26+ и [Flutter](https://docs.flutter.dev/get-started/install) 3.47+. На Debian и Ubuntu для сборки под Linux ещё понадобятся:

```bash
sudo apt install clang cmake ninja-build pkg-config libgtk-3-dev liblzma-dev
```

Запуск приложения со службой на своей машине:

```bash
cd core && make install-daemon     # Linux: ставит и запускает crocelld
cd ../app && flutter run -d linux
```

`CROCELL_SOCKET=/path/to/crocelld.sock` направит клиент на службу, запущенную вручную. Если работаете только с ядром, быстрее через CLI `crocell`, см. [Сборку из исходников](README.ru.md#сборка-из-исходников).

## Что где менять

- Разбор новой ссылки или формата конфига: `core/subscription`, рядом тест.
- Проверка нод: `core/probe`. Туннель и правила: `core/engine`. Служба: `core/daemon`.
- Всё, что на экране: `app/lib/ui`. Тексты на двух языках, `tr('Русский', 'English')`.
- API между клиентом и ядром: `proto/`, затем `make proto` в `core/`. Сгенерированный код руками не трогаем.
- mihomo: `core/third_party/mihomo`, и обязательно строка в таблице в его `CROCELL.md`, иначе следующее обновление потеряет правку.

## Перед пул-реквестом

```bash
cd core && make vet test
cd app && flutter analyze && flutter test
```

CI запускает те же команды, но нод для подключения у него нет. Если правка касается туннеля или проверок, напишите в PR, что проверяли руками, на какой системе и с каким протоколом. Для этого используйте свою ноду.

Один PR, одна правка. Если изменился интерфейс, приложите скриншоты.

## Как PR попадает в код

Репозиторий на GitHub это зеркало того, в котором я работаю, поэтому зелёная кнопка слияния не используется. Я применяю ваши коммиты там, авторство сохраняется, и они возвращаются в `master` на GitHub через зеркало. После этого я закрываю PR с комментарием.
